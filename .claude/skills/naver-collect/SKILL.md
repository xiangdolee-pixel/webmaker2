# 네이버 자료 모으기

고객 블로그 · 플레이스에서 홈페이지 재료를 모은다. **스크립트가 다 하므로 curl · 화면 열기를 손으로 되풀이하지 않는다.**

## 1. 한 번에 모으기

자료는 비공개 폴더 `_pc/<slug>/` 에 둔다(리포는 PUBLIC — 고객 원본을 사이트 폴더에 두지 않는다).

```bash
node .claude/skills/naver-collect/collect.mjs _pc/<slug> --blog <블로그 아이디나 주소> --place <플레이스 번호나 지도 주소>
"$LOCALAPPDATA/Programs/Python/Python312/python.exe" .claude/skills/naver-collect/sheet.py _pc/<slug>
```

- 블로그 아이디 = `blog.naver.com/<아이디>`. 플레이스 번호 = 지도 주소의 `place/<숫자>`(주소를 통째로 넘겨도 된다 — 따옴표로 감쌀 것). `naver.me` 짧은 주소는 `curl -sI` 로 Location 을 먼저 편다.
- 둘 중 하나만 있어도 된다. 글이 많은 블로그는 `--max 60` 처럼 최근 글만. 사진이 필요 없으면 `--noimg`.
- 다시 돌려도 받은 사진은 건너뛴다.

## 2. 읽는 순서 (토큰 아끼기)

1. `_pc/<slug>/CONTENT.md` **하나만** 읽는다 — 플레이스 요약 + 모든 글 본문(해시태그 · 블로그 단추 글자 뺀 것). 4만 자를 넘으면 처음 60줄(플레이스 · 분류)을 보고, `grep -n "^### "` 로 제목 목록을 본 뒤 필요한 글만 offset 으로 읽는다. 휴무 공지 · 옛 모집 글은 제목만 보고 넘긴다.
2. 사진은 `out/sheet*.jpg` 모음판만 본다(36장씩). 원본을 한 장씩 열지 않는다. 자세히 볼 것만 따로 연다:
   - 본문이 "(글 없음 — 그림만 있는 글)"인 글 = 안내 그림(가격표 · 포스터)에 내용이 있다 → 그 그림은 열어서 표 · 글로 옮긴다.
   - 로고(투명 PNG — 모음판에선 회색 바탕), 인사말 그림.
3. `raw/` 는 스크립트가 못 뽑은 값이 있을 때만(`raw/apollo.json` 에서 grep).

## 3. 모은 뒤 꼭 정리할 것 (`_pc/<slug>/PLAN.md` 첫머리에)

- **자료끼리 어긋나는 값**: 운영 시간 · 전화 · 주소 · 제공 서비스가 플레이스와 블로그, 옛 글과 새 글에서 다르면 최신 · 플레이스 값을 쓰고 "확인 항목"으로 사용자에게 보고한다.
- **지금은 안 하는 것**: 블로그 메뉴 · 옛 그림에만 있고 최근 글 · 사람 명단에 없는 서비스는 싣지 않는다("현재 제공하지 않습니다" 같은 문장을 찾을 것).
- **날짜가 있는 값**(가격표 · 지원금)은 기준 날짜를 함께 적는다.
- **사람 정보**: 블로그가 이름을 밝히지 않은 사람은 사이트에서도 밝히지 않는다. 포스터 속 이름을 옮기지 않는다.
- **사진 쓰임**: 업체가 올린 사진만(스크립트가 방문자 리뷰 사진은 받지 않는다). 아이 얼굴 · 이모지로 가린 얼굴이 있는 사진은 쓰지 않거나 손 · 물건만 나오게 자른다. 블로그의 AI 삽화 · 포스터는 그대로 쓰지 않고 내용만 옮긴다. 공간 사진은 원본 크기(보통 3840~6000px)라 그대로 줄여 쓴다.

## 4. 안 될 때

- 플레이스 "정보를 못 읽음" → 네이버가 화면을 바꾼 것. `raw/place-home.html` 에서 `__APOLLO_STATE__` 모양을 보고 collect.mjs 의 정규식을 고친다(고친 것은 스킬에 남긴다).
- 블로그 글 0개 → 비공개 블로그이거나 아이디가 틀림. `https://m.blog.naver.com/<아이디>` 가 열리는지 본다.
- 인스타그램 · 카카오 채널 · 옛 홈페이지는 이 스킬 범위가 아니다(따로 받는다).
