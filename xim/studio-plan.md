## 1. 지금 어떻게 돌아가나 (D:\ws\docs)

```
텔레그램 버튼 ─▶ tools\telegram_control.py (PC 상주, 4,700줄)
                   ├ claude -p "<단계 md>"  ×4~5회  (Top15 → 기사 6개 → 팩트체크 → 요약 패키지)
                   ├ python news_rss.py              (RSS 9곳, 몇 초)
                   ├ python gpt_slide_text.py        (Brave 의 ChatGPT 를 Playwright 로 조작, 6장)
                   ├ python gpt_thumbnail_maker*.py  (같은 방식, 썸네일 1장, 질문 4개는 텔레그램 버튼)
                   ├ python make_slideshow.py        (04_slideshow.html)
                   └ 폰UI: 대본 → job.json → phone_slides.py(ChatGPT) → phone_build.py → Cloudflare Pages
```

### 불편한 점 (사용자 말 그대로)
1. PC 가 켜져 있어야 한다. PC 로 다른 작업을 하면 Brave 를 닫아야 해서 겹친다.
2. 기록이 안 남는다. result 폴더를 매번 지우고 다시 만든다(`e`·`ee` 정리).
3. 한 번 돌리면 30분. 불필요하게 길다.
4. 텔레그램이 귀찮다. 웹에서 다 지시하고 싶다.

### 30분이 어디에 쓰이나 (로그 · 문서 기준 추정)
| 구간 | 시간 | 왜 |
|---|---|---|
| `claude -p` 기동 4~5회 | 8~12분 | 매번 새로 떠서 긴 md 규칙을 읽고, 단계마다 git 커밋 |
| 슬라이드 6장 (ChatGPT 브라우저) | 5~10분 | 3장 병렬 · 12초 시차 · 장당 150초 타임아웃 · 코드 렌더 재시도 |
| 썸네일 (ChatGPT 브라우저) | 3~5분 | 1차 생성 → 같은 채팅에서 교정 요청, 검수 |
| 텔레그램 왕복 · 질문 대기 | 사용자 시간 | 6개 고르기, 제목 · 인물 · 표정 · 제스처 |

**가장 큰 두 덩어리는 "ChatGPT 브라우저 자동화" 와 "claude -p 반복 기동"** 이다. 둘 다 API 로 바꾸면 사라진다.

## 2. 목표

1. **웹에서 지시** — xim 에 새 탭 하나. 폰 브라우저에서도 된다(텔레그램이 하던 "폰에서 시작" 역할 대체).
2. **기록이 쌓인다** — 회차마다 원고 · 교정본 · 유튜브 패키지 · 슬라이드 6장 · 썸네일 · 쇼츠 페이지가 날짜별로 남고, 다시 열어 보고 복사할 수 있다.
3. **PC 가 꺼져 있어도 돌아간다** — 클라우드(Cloudflare Worker)에서 끝까지.
4. **10분 안쪽** — 글 단계 3분 + 그림 단계 3~4분 목표.
5. **텔레그램 없이** — 알림이 필요하면 웹 푸시나 메일로.

## 4. "내 GPT 와 연결" 은 어디까지 되나 (중요)

- **ChatGPT 웹 계정(구독)** 은 밖에서 지시를 넣을 공식 통로가 없다. 지금처럼 **브라우저를 자동 조작**하는 수밖에 없고, 그래서 PC 가 필요하고 느리다.
- **공식 통로는 OpenAI API** 다. ChatGPT 구독과 **별개로 과금**된다. API 에는 "ppt1 스타일" 같은 **내 채팅 기억이 없다.**
- 그래서 **스타일 북**을 만든다: ppt1 스타일을 글로 적은 규칙(색 · 레이아웃 · 글꼴 느낌 · 불릿 3~4개 · 하단 배너) + 지금까지 잘 나온 슬라이드 **참고 이미지 3~5장**. 이미지 생성 요청마다 함께 보낸다(이미지 편집 엔드포인트가 참고 이미지를 받는다). 썸네일도 같은 방식으로 사섬 · 순섬 두 프리셋 + 인물 사진(★emoji 또는 업로드 사진)을 참고로 붙인다.
- 그래도 ChatGPT 결과가 더 낫다고 느끼면: **"내 ChatGPT 로 만들기" 스위치**를 두고, PC 도우미가 켜져 있을 때만 그 경로로 보낸다. 기본은 API.
- **시험을 먼저 한다** — 같은 원고 6장 + 썸네일 1장을 API 로 만들어 지금 ChatGPT 결과와 나란히 놓고 본다. 여기서 합격해야 2단계(그림)로 간다.

## 5. 화면 (xim 안)

### 5.1 작업 만들기
- **종류**: 사섬 본편 · 순섬 본편 · 폰UI 쇼츠 · 썸네일만
- **소스**: 웹 뉴스 자동(RSS, 현재 시각 기준 12시간) · 캡쳐 올리기(폰 · PC 에서 이미지 1~6장) · 글 직접 · 링크
- **스타일**: 사섬 / 순섬 (썸네일 색 · 인사말이 따라온다)
- **고르기 방식**: 완전 오토(클로드 추천 6개로 바로) / 내가 6개 고르기
- **그림 엔진**: 클라우드 API(기본) / 내 ChatGPT(PC 도우미 켜져 있을 때만 활성)
- **시작** 한 번이면 끝. 폰에서도 같은 화면.

### 5.2 진행 보기
- 단계 카드: 뉴스 후보 → Top15 → 6개 확정 → 기사 6 → 팩트체크 → 유튜브 패키지 → 슬라이드 6 → 검수 → 슬라이드쇼 → 썸네일. 각 카드에 걸린 시간 · 비용 표시.
- 실시간 갱신(몇 초마다 폴링, 화면 그대로 둬도 됨). **멈춤** 버튼.
- **6개 고르기**: 기사 15개를 카드로(제목 · 매체 · 국기 · 발행 시각 · 100자 요약 · 원문 링크), 체크 6개, 클로드 추천은 표시만. 텔레그램에서 15개 메시지 스크롤하던 것보다 훨씬 편하다.
- **썸네일 고르기**: 제목 5개 + 직접 입력 / 인물 명찰(등장 인물에서 자동 후보, 패스 가능) / 표정 20 · 제스처 20(기존 목록 그대로, "자동" 포함) / 인물 사진(내 사진 ★emoji · 업로드).
- 완전 오토면 선택 단계를 모두 건너뛴다.

### 5.3 결과
- 탭: **원고** · **슬라이드** · **슬라이드쇼** · **썸네일** · **유튜브** · **쇼츠**
- 원고(01 · 02 교정본 · 03 패키지)는 웹에서 바로 고치고 저장하면 **버전**이 쌓인다(되돌리기 가능).
- 슬라이드는 장별로 **이 장만 다시** 버튼. 썸네일도 **다시 만들기**(제목 · 표정 바꿔서).
- **슬라이드쇼** `…/studio/show/<작업id>` — 지금 `04_slideshow.html` 기능 그대로(왼쪽 1400px 슬라이드 · 오른쪽 500px 대본 · 큰 페이지 버튼 · 타이머 · 좌우 커서 · 본문 편집). 저장은 Ctrl+S 가 서버에 저장하는 것으로 바뀐다. 방송 때 이 주소를 띄운다.
- **유튜브** 탭: 제목 5 · 인트로 · 더보기란 · 등장 인물, 항목마다 **복사** 버튼.
- **쇼츠**(폰UI): 폰에서 열 주소 `…/p/<작업id>` 와 항상 최신을 가리키는 `…/p/latest`, QR, yt 제목 · 설명 · 태그 복사.

### 5.4 기록
- 날짜별 카드(썸네일 · 제목 · 채널 · 상태 · 소요 시간). 검색(제목 · 인물 · 키워드). 다시 열기.
- 폰UI 의 `topics_used.md`(같은 주제 중복 방지)는 DB 가 대신한다.

### 5.5 설정
- 스타일 프리셋: 슬라이드(ppt1) · 썸네일 사섬 · 썸네일 순섬 · 폰 세로 컷 — 각각 규칙 글 + 참고 이미지.
- 인물 사진: ★emoji 87장을 R2 에 올려 번호로 고른다(리포에는 올리지 않음, R2 비공개).
- 인사말 2종, RSS 피드 목록, 기본 모델(글 단계), 하루 최대 실행 횟수(과금 안전장치).

### 5.6 공통
- 모든 화면 폰 폭에서 깨지지 않게(CLAUDE.md 규칙). 폰에서 캡쳐 올리기 가능.
- xim 운영자 로그인(OTP) 뒤에만 보인다.

## 6. 파이프라인 재설계 (속도)

| 단계 | 지금 | 새 방식 | 예상 |
|---|---|---|---|
| 뉴스 후보 | PC python RSS | Worker 가 RSS 9곳 병렬 fetch | 5초 |
| Top15 + 추천 6 | `claude -p` | Claude API 1회, 구조화 출력(JSON) | 30초 |
| 6개 확정 | 텔레그램 버튼 | 웹 체크 (완전 오토면 생략) | 사용자 |
| 기사 6개 | 서브에이전트 6개 | Claude API **6개 동시**, 원문은 서버 web_fetch 도구 | 1분 |
| 팩트체크 | `claude -p` | Claude API 1회, 고칠 블록만 JSON 으로 | 40초 |
| 유튜브 패키지 | `claude -p` | Claude API 1회 | 30초 |
| 슬라이드 6장 | ChatGPT 브라우저 5~10분 | 이미지 API **6장 동시** + 스타일 북 | 1~2분 |
| 검수 | check_slides + 눈 | Claude 비전 1회(한국어 · 키워드 · 비율 · 숫자) → 불합격만 자동 재생성 1회 | 30초 |
| 슬라이드쇼 | make_slideshow.py | Worker 템플릿 렌더 | 즉시 |
| 썸네일 | ChatGPT 브라우저 3~5분 + 질문 | 이미지 API + 인물 참고 사진, 질문은 웹 | 1~2분 |

**합계 약 6~8분** (사용자가 고르는 시간 제외). 글 단계는 모델이 Opus 5.5 기준.

- **순섬(캡쳐) 경로**: 웹에서 이미지 1~6장 올림 → R2 → Claude 가 이미지를 읽고 기사 작성(지금 `01_ArticleMaker.md` 규칙). 이후 동일.
- **X 자동 캡쳐**(`x_bitcoin_news.py`)는 X 로그인이 필요해 클라우드로 못 옮긴다. PC 도우미에만 남기거나 폐기. 대신 폰에서 X 캡쳐를 바로 올리는 쪽이 자연스럽다.
- **폰UI**: 주제(자동 · 캡쳐 · 직접 · 글+이미지) → 40초 대본 + job.json(Claude API) → 세로 컷 3~4장(이미지 API, 안전영역 12~62% 규칙을 프롬프트와 검수에 넣음) → 페이지 빌드(`phone_build.py` 로직을 Worker 로) → `/p/<id>`. Cloudflare Pages 별도 배포가 필요 없어진다.
- 기존 md 규칙(문체 · 금지 어미 · 형식 · 검수 기준)은 그대로 **프롬프트 파일**로 옮긴다. 내용은 바꾸지 않는다.

## 7. 데이터

D1 `xim` 에 추가:
- `studio_jobs` — id, kind(main/phone/thumb), channel(사섬/순섬), source, status, options(JSON), title, started, finished, cost
- `studio_steps` — job_id, step, status, started, finished, log, tokens/cost
- `studio_docs` — job_id, kind(top15/article/factcheck/summary/script/phone_job), version, body, created
- `studio_assets` — job_id, kind(slide/thumb/capture/phone_cut/html), idx, r2_key, width, height, meta
- `studio_presets` — key, rules(text), ref_asset_keys
- `studio_topics` — 폰UI 중복 방지

R2 `xms-files` 에 `studio/<job_id>/…`, 프리셋은 `studio/presets/…`.
Worker 비밀값: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` (리포에 두지 않음).

## 8. 비용 (대략, 확인 필요)

- 글 단계(Opus 5.5, 입력 $4 · 출력 $20 / 100만 토큰): 회당 입력 6~8만 · 출력 1~1.5만 토큰 → **약 1,000원 안팎**. Sonnet 5.5 로 내리면 절반.
- 그림(OpenAI 이미지 API): 회당 7~8장(슬라이드 6 + 썸네일 1 + 재생성). 장당 요금은 구현 때 확인한다.
- 두 API 모두 Claude Code · ChatGPT **구독과 별개** 과금. 하루 최대 실행 횟수를 설정에 둔다.
- 돈을 안 쓰는 길은 지금처럼 PC 도우미(Claude Code + ChatGPT)로 돌리는 것인데, 그러면 PC 필요 · 속도 그대로다. 웹 화면 · 기록만 얻는다.
