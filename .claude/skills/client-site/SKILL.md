규칙 본문은 `CLAUDE.md`(0 ~ 10번 · 배포 · xim) · `GUIDELINES.md` 6번(AI 티 금지)에 있다. 여기는 **순서 · 사용자가 실제로 지적한 것 · 도구**만 적는다. 살아 있는 예: `neulhaerang/`(6쪽, 손으로 쓴 홈 + 작은 생성기), `kinderwill/`(21쪽, 전부 생성기).

## 1. 순서와 산출물

1. **자료 수집** — `naver-collect` 스킬. 지금 쓰는 홈페이지가 있으면 그 글도 전부 `_pc/<slug>/src/CONTENT.md` 로.
2. **사실 정리** — `PLAN.md` 첫머리에: 어긋나는 값(운영 시간 · 전화 · 사람 구성 · 지점) / 지금은 안 하는 것 / 날짜 있는 값(가격 · 지원금 기준일) / **확인 항목 표(항목 → 지금 넣은 가정)**. 사용자 답을 기다리지 않는다("가능한 자료에 충실하게 그냥 해줘") — 플레이스 · 최신 값으로 넣고 끝에 보고.
3. **기획 `PLAN.md`** — 사용자 지시(원문) · 방문자(누가 무엇을 찾나, 알고 싶은 순서) · 사업 묶음 · 메뉴 표(1단 → 2단 → 파일 → 담는 것) · 홈 구간(위 → 아래) · 뺄 것/꼭 넣을 것 · 그림 계획 표(쓰임 → 재료 → 방법) · 디자인 방향(색 · 글꼴 · 폭) · 기술 · 확인 항목. 본보기: `_pc/kinderwill/PLAN.md`.
4. **레퍼런스 3곳**(2절) → `ref/gdweb/REFERENCE.md`.
5. **레드팀 ①(기획)**(6절) → PLAN.md v2. *메뉴는 사용자가 직접 정하는 일이 많다 — 메뉴 표를 한 번 보여 주고 간다.*
6. **그림** — 로고 따기 · 사진 고르기 · (필요하면) GPT(5절). 한 장씩 눈으로 확인 → `prep_img.py` → `images/`.
7. **홈 시안** — 생성기부터 만든다(3절). 폰 히어로까지.
8. **찍어서 확인**(3절 크기 목록) → **레드팀 ②(시안)** → 고침. 2 ~ 3번 되풀이(킨더윌은 3차까지).
9. **하위 페이지** — 페이지 묶음별로 에이전트에게 모듈 하나씩(BRIEF 를 준다, 3절).
10. **전 페이지 점검** — 레드팀 ③ + `hovercheck.py` + 글꼴 다시 굽기 + `V` 올림.
11. **배포** `node deploy.mjs <slug>` → 확인(7절 1번 주의) → xms 메뉴 이름 · 주소가 사이트 메뉴와 같은지, 검색 제목 · 설명(xms `site_seo`), 파비콘, 공유 그림.
12. **커밋 · 푸시**(CLAUDE.md Git) · README 폴더 목록.
13. **메모리** `<slug>-project.md`(구조 · 사용자 지시 · 확인 항목 · 남은 일) + MEMORY.md 한 줄.
14. **보고** — 주소, 한 일 요약, **센터에 확인할 것 목록**, 남은 일. 짧게.

## 3. 기술 틀

**생성기(2쪽 넘으면 html 을 손으로 쓰지 않는다)** — 킨더윌 방식:
- `_dev/kit.py`: `V`(css · js · 그림 `?v=`) · `FV`(글꼴) · 상수(지점 · 전화 · 예약/블로그 주소 · 운영 시간 — **한 곳에만**) · `MENU`(1단 → 2단, 헤더 · 큰 메뉴 · 서랍 · 형제 탭 · 빵부스러기가 모두 여기서) · `img()`(크기는 `sizes.json`, lazy 기본) · 본문 부품(`sec` `head` `rows` `steps` `faq` `table` `tabs` `figure` `duo` `band` `scene` `quote` …) · 틀(`header` `footer` `doc` `subpage` `write`).
- `_dev/home.py`, `_dev/pages_<묶음>.py`(각각 `pages()` 가 `(파일, html)` 목록) · `_dev/build.py` 가 모두 찍고 **`_layout.html`(머리 · 빈 `<main>` · 꼬리, noindex)** 도 찍는다 — 게시판 · 회원 화면 틀(CLAUDE.md "게시판 · 회원 화면").
- 6쪽 안팎이면 늘해랑 방식도 된다: 홈은 손으로, `_dev/build-pages.py` 가 index.html 의 머리 · 꼬리를 잘라 하위 쪽에 끼움(홈 머리를 고치면 다시 실행).
- 실행: `PYTHONIOENCODING=utf-8 "$LOCALAPPDATA/Programs/Python/Python312/python.exe" <slug>/_dev/build.py`
- 여러 에이전트가 하위 쪽을 나눠 쓸 때: **맡은 `pages_*.py` 하나만**, kit · css · js 는 못 고치게 하고 필요한 새 모양은 보고로 받는다. 줄 문서 본보기 = `_pc/kinderwill/BRIEF.md`(만드는 방식 · 부품 목록 · 그림 이름 목록 · 글 규칙 · 확인 명령 · 보고 형식).

**머리(head) · 헤더에 꼭**
- 헤더 안 햄버거 옆에 `<span class="hd-account" data-xms-account></span>`(폰에서도 보이게, 색은 `--xa-bg` `--xa-fg`), 모든 하위 쪽에 `<main>`.
- 글꼴: `_dev/build-fonts.py`(킨더윌 것 복사) — 사이트에 쓰인 글자만 담은 Pretendard 한 파일 + 제목 글꼴 한 파일, 둘 다 `preload` + `font-display: block`, 바깥 Pretendard CSS 는 `media="print" onload` 로 뒤에. **글을 고칠 때마다 다시 굽고 `FV` · `@font-face ?v=` 올림.** 제목 글꼴은 OFL 확인 후 사용자에게 한 줄(써 본 것: 고운바탕, 나눔손글씨 펜, 나눔스퀘어라운드).
- 히어로 첫 장 사진만 `preload` + `fetchpriority="high"`(폰용 세로 사진 따로), 나머지 `loading="lazy"` + width/height.
- 지도 = xim 공용 지도 iframe(CLAUDE.md "네이버 지도"), 문의 폼 = 그 사이트 xms `site_inquiries`(bsf 방식), 예약 = 네이버 예약 링크. 폰은 아래 붙는 막대(전화 · 예약 · 길찾기) — 맨 위로 버튼과 겹치지 않게 `body .xms-top { bottom }`.
- 블로그 최신 글은 사이트 자체 Worker 를 두지 않고(자동 연결이 빠진다) 빌드 때 RSS → json → html(`kinderwill/_dev/blog.py`).

**사진 처리** — `prep_img.py`: webp, 히어로 1920(q78) · 화면 폭 띠 1600 · 보통 1000 · 인물 카드 360, 폰 히어로 1000 세로. 크기 표 `sizes.json`. 저해상도 실제 사진은 AI 로 다시 만들지 말고 키우기(메모리 no-ai-look-photos).

**공유 그림 · 파비콘** — `_pc/<slug>/out/og.html` 을 1200×630 으로 찍어 `images/og.jpg`(실제 사진 + 큰 글자). 파비콘 32 · 192 · apple-touch.

**화면 찍기** — `_pc/<slug>/shot.py`(playwright, `channel="msedge"` headless, 빈 포트에 미리보기 서버를 스스로 띄움):
`python shot.py <페이지> 1440x900 390x844 --full` / `--y=스크롤` / `--hover=선택자` / `--click=선택자` → `out/shots/*.jpg` 를 Read 로 본다(긴 것은 Pillow 로 잘라서). 출력의 **넘침 0 · 깨진그림 [] · 작은글자 [] · 밖으로 [] · 오류 []** 여야 통과.
- 히어로: 1920×940 · 1536×730 · 1280×620 · 1366×650 · 1180×760 · 844×390(폰 가로) + 390×844 · 360×740 · 320×640.
- 하위 쪽: 1440×900 · 390×844 전체. 로테이션 히어로는 장마다.

**hover 대비** — `python hovercheck.py` : 모든 버튼 · 알약 링크에 올려 대비 3 미만을 출력. 0 이어야 한다.

## 4. 사용자가 실제로 지적한 것 (만들기 전에 읽고, 보고 전에 다시 본다)

취향 요약(에이전트에게 그대로 넘긴다): *따뜻 · 친절 · 약간 고급 · 깔끔, 작은 곳이라도 잘 갖춰 보이게, 빈약 금지, AI 티 금지, 작은 글자 금지, 흰 바탕, 끝선 하나, 속도 최우선.*

**A. 첫인상**
1. **빈약한 히어로 금지** — 흰 바탕에 왼쪽 글 + 오른쪽 사진은 "너무 약해 · 빈약하다 · 성의없다". 첫 장면은 **꽉 찬 사진 위에 글**, 글 자리에만 그라데이션. 그 아래도 사진 띠 · 어두운 사진 구간 · 카드 구간으로 채운다. 지금 사이트에 슬라이드가 있으면 "로테이션되어야지"(장마다 사진 + 글, 진행 표시 · 멈춤, 첫 장만 preload, 글 묶음 높이 고정).
2. **폰 히어로** — "정리가 안 된 느낌 · 있어 보이지도 않는다"를 세 번 들었다. 폰은 덜어 낸다(작은 줄 · 큰 제목 · 짧은 설명 · 단추 하나 · 얇은 안내 띠), 세로 사진 따로, 글 왼쪽 선 하나. 점검 6가지는 메모리 hero-phone-check. 낮은 화면은 CLAUDE.md 8번(`--hu`).
3. **"AI 로 만든 느낌"** — 첫 배포본에 들은 말. 원인: 모든 구간이 같은 머리 틀 · 흰 테두리 상자 격자 · 둥근 네모 아이콘 · 알약 칩 무더기 · 3:2 썸네일만 · 글꼴 한 가지 · 균등 격자. 처음부터: 브랜드 모티프 2 ~ 3개(로고에서), 제목 글꼴 하나 더, 사진을 주인공으로(화면 폭 띠 · 두 장 겹치기 · 캡션), 상자 대신 줄 + 번호, 구간 2 ~ 3개마다 큰 사진이나 인용문. 정리본: `_pc/kinderwill/DESIGN2.md`.
4. **"정보만 있고 감성이 없다 · 글자만 많다"** — 사진 · 카피 · 색으로 한 겹 더. 단 **카피는 새로 짓지 말고 고객이 이미 쓴 문장**(인사말 · 약속 · 선생님 한마디 · 블로그 소개)에서 — "카피를 최대한 여기 홈페이지에 있는 걸 이용해줘". 다듬기는 띄어쓰기 · 오타 · 과장 낱말만.
5. **자랑거리는 다 싣는다** — 방송 · 기사 · 수상 사진은 "자랑이잖아". 원본 그대로(크기만).

**B. 디테일**
6. **작은 글자 금지** — 본문 17 ~ 18px, 가장 작은 글자 16px(캡션 · 꼬리 · 표 포함). 위 메뉴 글자도 크게. 확인: shot.py "작은글자".
7. **좌우 끝선** — 헤더 · 히어로 글 · 본문 · 꼬리가 한 `.wrap`(1240 ~ 1280). 본문만 좁히지도, 꼬리만 따로 패딩 주지도 않는다. 왼쪽이 비어 보이면 안 됨.
8. **바탕은 흰색** — 크림 · 살색 바탕은 "AI 같다". 구분은 옅은 회색. **예외: 고객 홍보물 · 간판의 분위기가 그 색일 때**(늘해랑 아이보리) — 고객 자료가 근거일 때만, 그리고 구간 한두 곳의 옅은 색 면은 된다.
9. **로고는 원본에서 오린다** — GPT 로 다시 그리면 글자가 바뀐다. 원본이 간판 사진뿐이면 GPT 로 평평하게 편 뒤 원본과 나란히 대조. "눈에 안 띄고 글자가 작다" → 머리에서 충분히 크게, 색은 간판 실물 색.
10. **글줄 끊김** — "한 사람 한 / 사람의" 금지. 묶을 말은 `<span class="nb">`(nowrap) + `text-wrap: balance/pretty`, 제목은 폭마다 찍어 본다(한두 글자만 떨어지는 줄 금지).
11. **hover 때 글자가 사라지면 안 됨** — `.ft a:hover` 같은 구역 규칙이 버튼 hover 를 이기지 않게, 배경 · 글자 · 테두리 · 아이콘을 한 묶음으로(CLAUDE.md 7번). 확인: hovercheck.py.
12. **웹폰트 깜빡임** — "새로고침할 때마다 다른 폰트로 보이다가 바뀌어" → 3절 글꼴.
13. **펼침 칸은 닫힐 때도 부드럽게** — 참고 `neulhaerang/js/site.js` '펼침 칸'.
14. **하위 메뉴 탭 잔상** — 페이지를 옮기는 탭은 스크립트로 배경을 옮기지 않고 `@view-transition` 으로 한 번에(메모리 tab-no-ghost-on-navigate, `neulhaerang/css/style.css` `.tabs a.on`).
15. **사진 띠는 "알아서 움직여야"** — scrollLeft 가 아니라 `transform` 으로 흘린다(덜덜거림).
16. **꼬리** — 카카오 · 블로그 · 인스타 동그란 아이콘(인라인 SVG, hover 반전), 지점 연락처 · 운영 시간, "홈페이지 제작문의". 연출 사진 안내 문구 같은 변명 문장은 넣지 않는다.

**C. 사진 · 글의 선**
17. **AI 티 나는 사진 금지** — 기본은 고객의 실제 사진. GPT 는 사용자가 시켰거나 물어본 뒤에만, "같은 공간을 DSLR 로 다시 찍은 듯"(구조 · 가구 · 소품 그대로). **사람 얼굴이 나오는 실제 사진은 GPT 에 넣지 않고 원본을 오려 쓴다.** 새로 만드는 연출 사진은 얼굴 없이(손 · 뒷모습).
18. **간판 글자** — GPT 가 간판 낱말을 바꾼다("서브비주얼 이거 글자 깨진다"). 프롬프트에 글자를 한 자씩 적고, **결과의 글자 부분을 확대해 읽는다**(모음판 통과 금지). 틀리면 다시 만들거나 글자가 안 보이는 구도로. 페이지 머리에는 간판이 크게 보이는 사진을 피한다.
19. **글** — 자료에 있는 것만(숫자 · 자격 · 금액을 지어내지 않음), 과장 낱말("최고 · 완치 · 검증된") 금지, 효과는 단정하지 않음, 가격 · 지원금엔 기준일. 상담 · 치료 업종: 사례 · 후기 글 · 내담자 작품 · 리뷰 인용은 기본으로 빼고(사용자가 "리뷰를 홈에"라고 하면 이름 가린 한 문장 발췌), 진단 아님 · 비밀보장 예외 · 위기 전화 고지를 넣는다.
20. **용어** — CLAUDE.md "용어 금지". 고객 개인정보 · 원본 파일은 `_pc/` 에만.

## 5. GPT 로 사진 다듬기 (사용자가 시켰을 때)

- 도구: `_pc/kinderwill/gpt_img.py` + `jobs.json`(`{이름: {src, kind: space|new|class|team|raw, p}}`) — 머리 주석의 환경변수 그대로. 종류별 기본 지시(`BASE`)가 이미 다듬어져 있으니 복사해 업종 낱말만 바꾼다. 늘해랑 것(`_pc/neulhaerang/gpt_photo.py`)은 히어로용 지시 예(가로 16:9 "왼쪽 절반은 빈 벽 — 글자 올릴 자리" / 폰 세로 2:3 "위 55% 는 빈 벽").
- 결과는 **한 장씩 Read 로 열어** 본다: 다른 방 · 다른 가구를 지어냈으면 버린다, 간판 글자(4절 18), 사람 손가락 · 스티커 흔적. 이미 AI 로 손본 고객 사진은 원본으로 쓰지 않는다.
- 다시 만들 사진이 크게 쓰이는 자리에 있으면 그동안 다른 사진으로 바꿔 보여 준다(`kit.SIGN_HOLD` 방식).

## 6. 레드팀 돌리는 법

에이전트는 **만든 사람의 설명 없이** 파일 경로만 받는다(내 결론을 주면 그대로 확인해 준다). 공통 요구 문장:
> 칭찬 · 총평 · 좋은 점은 쓰지 마라. 가차 없이 문제만. 심각도 순(치명 → 큼 → 작음)으로, 항목마다 ① 무엇이 ② 어디(파일 · 화면 · 좌표) ③ 왜 문제인지(누가 어떤 손해) ④ 어떻게 고칠지. 추측이면 추측이라고 쓴다. 고치지는 말고 보고만.

**① 기획용** — 줄 것: `PLAN.md`, `CONTENT.md`, 사용자 지시 원문. 볼 것: 처음 온 사람(폰)이 3번 안에 답을 찾나 / 메뉴 이름이 고객 말인가 · 겹치나 / 자료와 어긋난 사실 · 지어낸 숫자 / 법 · 윤리 위험(과장 광고, 후기, 개인정보, 아이 얼굴) / 빠진 것(가격 · 예약 길 · 위치) / 홈 구간에 실제 내용이 있나(빈 구간) / 기존 사이트와 똑같아 보일 위험.

**② 시안용** — 줄 것: 찍은 화면 경로 목록(3절 크기 전부) + 레퍼런스 3곳 캡처 폴더 + 4절 점검표. 볼 것: 4절 1 ~ 20 을 하나씩 / 레퍼런스와 나란히 놓았을 때 밀도 · 사진 쓰임 · 글자 위계가 떨어지는 곳 / "AI · 템플릿 같다"는 인상을 주는 요소 이름 대기 / 폰 히어로 / 낮은 화면. 화면을 **직접 열어 보고** 좌표로 말하게 한다.

**③ 전 페이지 점검용** — 줄 것: 사이트 폴더, 페이지 목록, shot.py · hovercheck.py 쓰는 법. 시킬 것: 모든 페이지를 1440 · 390 전체로 찍고 **메뉴 · 탭 · 펼침 · 버튼을 다 눌러 본다** — 깨진 링크 · 숨은 탭 안의 못 가는 링크, 넘침, 작은 글자, 깨진 그림, 표가 폰에서 잘리는지(가로 밀기 안내), 같은 사진 중복, 페이지끼리 어긋난 사실(전화 · 시간), 문의 폼, 탭 전환, 글꼴에 빠진 글자, 콘솔 오류, 속도(요청 수 · 첫 화면에 lazy 아닌 그림). 로컬 미리보기로만(배포 주소를 두드리지 않는다 — 7절 1번).

고친 뒤에는 같은 화면을 다시 찍어 내가 직접 확인한다. 레드팀 보고는 사실이 아닐 수도 있다 — 화면으로 확인한 것만 고친다.

## 7. 자주 난 사고

1. **xim 보안 차단** — 배포 뒤 없는 주소(.py · 아직 없는 메뉴 링크)를 여러 번 불러 이 PC 주소가 막혔다. 배포 확인은 `/` 200 + 리포 파일 **하나** 404 만. 링크 점검은 로컬에서. 막히면 xim DB `sec_blocks` 에서 풀고 `sec_allow` 확인.
2. **GPT 가 엉뚱한 방 · 틀린 간판** — 5절. 썸네일로만 보고 넘기지 않는다.
3. **같은 이름 파일을 바꾸고 `?v=` 를 안 올림**(로고가 옛 것으로 보임) — `kit.V` 한 곳을 올린다. 글꼴은 `FV`. CLAUDE.md 8-1.
4. **글을 고친 뒤 글꼴을 다시 안 구움** — 제목 몇 글자만 다른 글꼴. build 뒤 build-fonts 를 늘 같이.
5. **홈 머리를 고치고 하위 쪽 · `_layout.html` 을 다시 안 찍음** — 게시판 화면만 옛 헤더. 생성기를 통째로 다시 돌린다.
6. **xms 메뉴와 사이트 메뉴가 달라짐** — 첫 배포 때 헤더 링크가 xms 메뉴로 한 번만 들어간다. 그 뒤 메뉴 이름 · 주소를 바꾸면 xms `menus`(그 site 것만)도 맞춘다.
7. **여러 에이전트가 같은 css · kit 을 동시에 고침** — 3절대로 모듈만 맡긴다.
8. **고객 원자료를 사이트 폴더에 둠** — PUBLIC. 포스터 속 이름 · 가격표 그림을 그대로 올리지 않는다.
